# 인형뽑기 속 인형 — v2 제작 계획 (인계 문서)

새 세션에서 이 문서를 먼저 읽고 시작한다. 작업 전에 요구사항을 정리해 확인받고, OK를 받은 뒤 시작하는 것이 사용자의 작업 방식이다.

## 게임 한 줄 소개

인형뽑기 기계 속 한정판 햄스터 인형이 되어, 손님의 집게를 피해 끝까지 버티는 3D 게임.

## 규칙과 재미 포인트 (원안)

- 손님은 동전 5개를 가지고 있고, 5번의 시도를 모두 버티면 승리. 출구 구멍으로 떨어지면 패배.
- 집게가 내려오기 전에 바닥에 그림자가 먼저 드리워져서, 그림자를 보고 피한다.
- 다른 인형 밑에 파묻히면 집게가 위에 있는 인형을 대신 집어간다.
- 잡히면 연타로 버둥거려 빠져나온다. 집게 힘은 매번 랜덤이라 힘 빠진 집게면 저절로 떨어지기도 한다.
- 유리 너머로 손님 얼굴이 거대하게 보이고, 표정이 기대 → 짜증 → 포기로 바뀐다.
- 짜증 난 손님이 유리를 쾅 치면 기계가 흔들려 인형 더미가 무너진다(숨어 있다가 드러날 수 있음).
- 내 대신 동료 인형들이 하나둘 뽑혀간다.
- 패배 엔딩: 손님 품에 안겨 기념사진 / 승리 엔딩: 손님이 포기하고 떠남.

## 확정된 결정

- 3D, 고퀄리티. 2D는 하지 않는다.
- 도구: Three.js 웹 게임 (v1과 동일: three + cannon-es, esbuild로 HTML 한 파일로 묶음).
- 시점: 3인칭. 햄스터 뒤쪽 위에서 따라가며, 인형 더미 너머 유리 밖으로 손님의 거대한 얼굴이 보인다.
- 분위기: 밤의 오락실. 바깥은 어둡고 네온, 기계 안은 따뜻하고 밝게.
- 주인공: 한정판 햄스터. 동료 인형은 곰, 토끼 등 귀여운 봉제인형.
- 조작: 점프 없음. 인형 더미 위를 밍기적밍기적 엉금엉금 기어가기 + 인형 사이로 파고들기. 잡히면 연타 탈출.
- 규칙과 게임 흐름은 v1을 이어받는다.
- 조작 기기: PC 키보드 먼저, 모바일 터치는 나중.

## v1 (참고 자료: `v1_reference/`)

사용자가 이전에 만든 3D 시안의 소스. `src/claw.js`가 인형뽑기 게임이고, `src/phone.js`는 두 번째 아이디어(숨는 스마트폰)이다. 동전 5개, 숨은 정도, 연타 탈출, 손님 표정 8종, 유리 치기, 폴라로이드 엔딩, 효과음까지 규칙은 거의 구현되어 있으니 로직은 여기서 가져온다.

v1이 저퀄로 보이는 이유:

- 전부 만화풍 단색 재질에 화면 전체가 밝은 파스텔 한 톤이라 깊이감과 시선이 모이는 곳이 없다. 유리는 평면 그림 한 장이다.
- 인형이 공 여러 개를 붙인 모양이고 충돌도 공 하나라서, 바닥에 한 겹으로 흩어져 굴러다닌다. 더미가 아니어서 파묻히는 재미가 약하다.
- 손님 얼굴이 구에 눈코입을 붙인 형태라 어색하고 표정 변화가 잘 안 읽힌다.
- 오락실 배경이 색 상자들이다.
- 주인공이 곰이고, 걷고 점프하는 조작이다.

## v2 요구사항

1. 렌더링: 천 재질(보송한 결, 가장자리 광택), 환경광(HDRI), 부드러운 그림자, 후처리(접촉 음영, 은은한 빛 번짐, 미니어처 느낌의 심도, 색 보정), 반사와 손자국이 있는 진짜 유리.
2. 인형: 전문가 수준의 봉제인형 모델. 짧은 털 표현. 눌리면 찌그러지는 말랑한 변형.
3. 더미: 인형 수를 늘려 여러 겹으로 쌓이게 한다. 충돌 형태도 공 하나가 아니라 인형 모양에 맞춘다.
4. 움직임: 무게감 있는 기어가기, 파고들기.
5. 손님: 어두운 매장에서 기계 불빛을 아래에서 받은 얼굴이 유리 반사 너머로 보이게 한다. 표정(기대 → 짜증 → 포기)이 한눈에 읽혀야 한다.
6. 배경과 연출: 오락실다운 배경, 카메라 연출, 효과음.

## 에셋 계획 (새 환경에서 직접 찾아 넣기)

품질 차이는 캐릭터 모델에서 가장 크게 난다. 네트워크가 열린 환경에서 직접 찾아 내려받아 넣는다.

찾을 것:

- 햄스터 봉제인형 모델 1개 (주인공)
- 동료 봉제인형 4~5종 (곰, 토끼, 고양이, 병아리, 개구리 등). 그림체가 서로 맞아야 한다.
- 밤 실내용 HDRI, 천·카펫 재질 텍스처
- 오락실 배경 소품 (다른 게임기, 네온 간판 등)
- 손님 얼굴은 어색해지기 쉬우므로 코드로 만드는 것을 기본으로 하고, 좋은 스타일 모델이 있으면 검토한다.

찾을 곳: Poly Haven(HDRI·텍스처, CC0), ambientCG(텍스처, CC0), Poly Pizza, Kenney, Quaternius, Sketchfab(다운로드 가능·라이선스 표시된 것), itch.io, OpenGameArt.

규칙:

- 라이선스를 반드시 확인한다. CC0를 우선하고, CC-BY는 출처 표기를 전제로 쓴다. 상업적 이용 불가(NC)나 라이선스가 불분명한 것은 쓰지 않는다.
- 쓴 에셋은 `claw_doll/CREDITS.md`에 이름, 작가, 출처 주소, 라이선스를 기록한다.
- 모델 형식은 GLB. 용량이 크면 줄여서 넣는다.
- 맞는 무료 모델이 없으면 사용자에게 알린다. 대안은 AI 3D 생성 도구(Meshy, Tripo 등)로 사용자가 GLB를 만들어 주는 것이다. 이 경우 코드로 만든 임시 모델의 정면·측면 그림을 기준 그림으로 제공해 그림체를 통일한다.

## 진행 순서

1. 룩 시안: 게임 규칙 없이 기계 안, 햄스터, 인형 더미, 손님 얼굴, 밤의 오락실이 담긴 장면 하나를 만들어 사용자에게 보여 주고 그림을 확정한다. 기어가기와 파고들기 조작감도 여기서 확인한다.
2. 이식: 확정된 화면에 v1의 규칙을 옮긴다.
3. 연출과 엔딩: 손님 연출, 유리 쾅, 엔딩, 소리를 마무리한다.

단계마다 사용자가 플레이해 보고 피드백을 준 뒤 다음으로 넘어간다.

## 폴더 상태

- `PLAN.md`: 이 문서
- `src/`, `assets/`, `build.mjs`: v2 소스. `npm install` 후 `npm run build`를 하면 `dist/claw_doll.html` 한 파일이 나온다(dist는 저장소에 올리지 않음).

1단계 룩 시안 진행 중. 들어간 것: 밤의 인형뽑기장 배경(흰 기계가 통로 양쪽으로 늘어선 모습), 따뜻하게 밝은 기계 안, 스캔 원단 재질의 인형 144개 더미, 한정판 햄스터(빨간 목도리·금관·머리 위 표시), 엉금엉금 기어가기와 파고들기, 숨은 정도 표시, 돌아다니는 집게, 손님(실제 손 모델, 표정 3종은 숫자키 1·2·3).

남은 것: 손님 얼굴과 머리카락을 외부 모델로 바꿀지 결정(아래), 사용자 PC에서의 속도 확인, 2단계 규칙 이식.

손님 얼굴 후보: three.js 예제의 `facecap.glb`(표정 변형 52종이 들어 있으나 라이선스 표기가 불분명하고 머리카락이 없음), `LeePerrySmith.glb`(실사 머리 스캔, CC BY 3.0, 표정 변형 없음, 머리카락 없음). 둘 다 귀여운 봉제인형 그림체와 어긋날 수 있어 사용자 확인이 필요하다.
