# 지우개 따먹기

학교 책상 위에서 지우개를 번갈아 튕겨 상대 지우개 위에 올라타면 이기는 3D 게임. Three.js + Rapier 3D.

## 실행

```bash
npm install
npm start
```

http://localhost:5173 을 연다. 이 서버 하나가 게임 화면과 온라인 대전(WebSocket)을 함께 내준다.

- 개발 중에는 `npm run dev`(새로 고침할 때마다 다시 묶음).
- 혼자 하기·둘이 하기만 쓸 거면 `npm run build` 뒤 `dist/index.html`을 더블클릭해도 된다. 온라인은 서버 주소로 열어야 한다.
- 검증: `npm test`(물리·판정, 버그 점검, 모양별 접촉, 겉모습 맞춤, 온라인 서버), `node test/browser.cjs`, `node test/browser_online.cjs`(실제 브라우저).

## 온라인 대전

### 친구와 하기
1. 표지에서 **온라인** → 별명 입력 → **친구와 할 방 만들기**.
2. 화면의 **초대 링크**(또는 5글자 방 코드)를 친구에게 보낸다. 링크는 지금 접속한 주소를 기준으로 만들어진다.
3. 친구가 링크를 열면 같은 방에 들어온다. 각자 지우개를 고르고 **준비**를 누르면 시작한다.
4. 끝나면 둘 다 **재대결**을 눌러야 새 판이 시작된다. 선공은 판마다 바뀐다.

### 모르는 사람과 하기
**누구나 들어오는 방 만들기**로 공개 방을 만들면 다른 사람의 "기다리는 공개 방" 목록에 방 이름·인원·대기 상태가 보이고, 거기서 들어올 수 있다. 비공개 방은 목록에 나오지 않는다.

### 어디서 접속할 수 있나
| 상황 | 방법 |
|---|---|
| 같은 컴퓨터의 브라우저 두 개 | http://localhost:5173 |
| 같은 공유기의 다른 기기 | 서버를 켠 컴퓨터에서 `npm start`를 하면 출력되는 `http://192.168.x.x:5173` 주소 |
| 인터넷의 친구 | 이 서버를 WebSocket 연결을 유지할 수 있는 곳에 올려야 한다(아래). 정적 사이트 호스팅만으로는 안 된다 |

### 인터넷에 올리기
`Dockerfile`이 들어 있다. 컨테이너를 돌려 주고 WebSocket을 지원하는 서비스(Render, Fly.io, Railway, 직접 빌린 서버 등)에 이 폴더를 올리면 된다.

```bash
docker build -t eraser-duel .
docker run -p 8080:8080 eraser-duel
```

- 서비스가 `PORT`를 정해 주면 그 값을 쓴다. 환경 변수는 `.env.example` 참고.
- HTTPS로 서비스되면 화면이 자동으로 `wss://`로 붙는다. 화면과 서버를 다른 주소에 둘 때는 화면 주소 뒤에 `?server=wss://서버주소/ws`를 붙인다.
- 상태 확인: `/health` (방 수, 접속자 수).
- 서버는 한 대로 돈다(방 정보를 메모리에 둔다). 서버를 다시 켜면 진행 중이던 방은 사라진다.

### 서버가 정하는 것과 화면이 하는 것
| 서버(공식 결과) | 브라우저(표시) |
|---|---|
| 방과 자리, 준비 상태, 정원(2명) | 받은 방 정보 그리기 |
| 차례와 턴 번호, 발사 허용 여부 | 조작 잠금, 버튼 표시 |
| 게이지 시간과 최종 파워 | 받은 게이지 시각에서 이어 그리기 |
| 물리(1/240초 고정 간격), 걸침·낙하 판정, 승패 | 받은 상태 사이를 보간, 먼지·별·꽃가루 같은 연출 |
| 경기에 쓰는 물리 설정(기본값 고정) | 없음. 개발자 패널은 온라인에서 숨겨지고, 서버에는 설정 변경·상태 복원·임의 발사를 받는 창구 자체가 없다 |

- 통신은 WebSocket(JSON)이다. 턴제에 가끔 상태를 밀어 주는 구조라 양방향 연결 하나면 충분하고, 서버에서 같은 물리 코드(`src/game.js`, `src/sim.js`)를 그대로 돌릴 수 있어서 골랐다.
- 상태 전송은 움직일 때 초당 30번, 조준 중에는 5번. 메시지마다 경기 번호·턴 번호·순번이 있어 지난 경기나 순서가 뒤바뀐 상태는 버린다.
- 발사 요청에는 요청 번호와 턴 번호가 있어 중복·지난 요청은 거절한다. 방향·파워 값은 숫자 범위를 검사한다.
- 누르는 힘은 서버가 잰다. 손을 뗄 때 브라우저가 "내 화면에서 잰 누른 시간"을 함께 보내면, 서버는 측정한 왕복 지연의 절반 + 0.06초(최대 0.25초)까지만 되돌려 준다. 그 범위를 넘는 값은 잘라 낸다.
- 재접속: 처음 접속할 때 받은 비밀 토큰(탭 단위 저장)으로만 같은 자리로 돌아온다. 끊기면 30초 기다리고, 안 돌아오면 기권 처리한다. 스스로 나가면 즉시 상대 승리. 한 차례 제한 시간은 60초.

## 조작

| 조작 | 키 | 마우스·화면 |
|---|---|---|
| 누를 곳 고르기 | ← → 또는 A D | 지우개 위의 색 점을 누르거나 ◀ ▶ |
| 꾹 눌렀다 떼기 | Space를 누르고 있다가 떼기 | 색 점이나 "꾹 누르기" 버튼을 누르고 있다가 떼기 |
| 한 판 더 | R | 결과 창의 한 판 더 |

- 지우개는 **누른 자리의 반대쪽**으로 튀어 나간다. 방향을 따로 정하는 화살표는 없고, 화면의 화살표는 튀어 나갈 쪽을 보여 줄 뿐이다.
- **누르고 있는 시간이 힘**이다(1.3초에 최대). 최대에서 0.6초를 더 버티면 손가락이 미끄러져 저절로 튕긴다. 살짝 건드린 것(0.15초 미만)은 취소된다.
- 누름 자리의 색: 초록 = 끝(곧게 나감, 쉬움), 노랑 = 옆(세게 누르면 굴러감), 빨강 = 꼭짓점(높이 뜨고 어디로 튈지 읽기 어려움), 파랑 = 안쪽(낮게 미끄러짐).
- 누름 자리는 지우개 종류마다 다르고, 지우개가 뒤집히거나 옆으로 서면 그때 위로 온 면의 자리를 쓴다.

표지에서 **혼자 하기**(컴퓨터 상대, 지우개 따 모으기), **둘이 하기**(한 화면에서 번갈아), **온라인**을 고르고 지우개를 고른 뒤 시작한다.

## 지우개 18종

보통, 새것(각져서 꼭짓점에서 크게 튐), 닳은(모서리가 둥글어 미끄러짐, 꼭짓점 자리 없음), 반토막, 납작, 정사각, 길쭉이, 미술(크고 무겁고 말랑), 꼬마, 점보, 탱탱. 크기·무게·마찰·반발·모서리 반경·누름 자리 구성은 `src/config.js`의 `TYPES`, `SPOT_SETS`에 있다.

모양 지우개 7종: 곰, 토끼, 거북이, 레슬러, 덩치, 육각(연필처럼 구르는 육각 기둥), 삼각(위에 올라타기 어려움). 충돌 모양은 상자·원통·공·볼록 다면체 조각(`parts`)을 붙여 만든다. 무게중심과 바깥 치수는 `shapeOf()`가 조각에서 계산한다. 귀·팔다리가 실제로 책상과 상대에 걸린다.

### 겉모습(그리는 모양)

그리는 모양은 충돌 모양과 따로 만들고 물리에는 영향을 주지 않는다(`src/look.js`, `src/lookgeo.js`).

- 직육면체 지우개 11종: 외부 CC0 지우개 모델(`assets/models`, 출처는 `CREDITS.md`)을 충돌 상자 크기에 맞춰 늘린다. 모서리 폭은 원본 비율을 지키고 종류의 모서리 반경(`round`)에 따라 넓히거나 좁힌다. 모델의 노멀맵으로 고무 표면의 패임을 살리고, 색과 때는 모델 UV 위에 직접 구워 그린다: 종이 띠 밖으로 나온 끝은 더 둥글게 닳고 흑연이 묻어 있으며, 윗면에 연필 자국이 있다. 새것은 깨끗하고 닳은 것은 가장 더럽다.
- 띠지: 고무 단면을 감싸는 종이 관. 윗면 이름표(1P/2P 동그라미, 이름), 옆면 설명 띠, 바닥 바코드, 모서리 쓸림·끝 해짐·접힌 금·연필 낙서.
- 모양 지우개 7종: 충돌 조각을 안쪽으로 둥글린 거리장(SDF)으로 부드럽게 잇고 주둥이·발·가슴·등딱지 무늬 같은 얕은 돋을새김·오목새김을 더해 곡면을 뽑는다(표면 그물). 무늬는 꼭짓점 색으로 칠하고(경계는 0.5mm에 걸쳐 섞음), 눈·코·입은 따로 붙인다. 고무를 찍어 낸 틀의 이음선(가장 넓게 잘리는 높이의 가는 턱), 구석의 그늘, 때와 흑연 얼룩, 쓸려 밝아진 곳, 고무 잔 패임 노멀맵을 더한다.
- 색은 1P 파랑, 2P 주황 계열을 지키고 종류마다 밝기만 조금 다르다.
- 맞춤 검사(`node test/look.mjs`, `npm test`에 포함): 모양 지우개의 겉면 양쪽 끝이 충돌 모양 끝과 2.5mm 안(지금 최대 0.9mm), 겉모습 부피 중심이 충돌 무게중심과 2.5mm 안(지금 최대 0.9mm)인지, 뒤집힌 면이 없는지 본다. 잇는 부분의 부풀음은 충돌 모양의 바깥 상자에서 잘라 책상에 파묻혀 보이지 않게 했다.
- 고르기 화면의 그림은 같은 겉모습을 작은 텍스처로 그린다. 화면이 바로 뜨도록 한 장씩 나눠 그린다(`view.thumbInto`).

고르기 화면의 능력치(속도, 튀는 높이, 균형, 무게)는 정해 넣은 숫자가 아니라 `node tools/measure_stats.mjs`가 같은 조건으로 실제로 튕겨 잰 값이다(`src/stats.json`). 물리 설정이나 지우개를 바꾸면 다시 돌린다.

혼자 하기에서는 보통 지우개 하나로 시작한다. 이기면 컴퓨터가 꺼낸 지우개를 따고, 지면 쓴 지우개를 뺏긴다(마지막 보통 하나는 남는다). 필통은 이 브라우저에만 저장된다.

## 규칙

- 지우개가 멈췄을 때 상대 지우개에 실제로 받쳐진 채 0.8초를 버티면 위에 있는 쪽이 이긴다(누구 차례였는지는 상관없다).
- 책상 아래로 떨어지면 떨어진 쪽이 진다. 둘 다 떨어지면 무승부.
- 승패가 없으면 둘 다 멈춘 뒤 차례가 넘어간다.

## 난이도: 지우개의 자세를 읽어야 한다

- 일반 경기는 두 지우개가 40cm 떨어져, 매번 다른 각도로 놓인 채 시작한다. 첫 턴에 올라타는 발사는 방향 21 × 파워 18 = 378발 가운데 2~8발(약 1.5%)뿐이라 보통은 접근과 자리 잡기가 필요하다(`node test/match.mjs`).
- 화살표는 "미는 방향"이지 도착 경로가 아니다. 손가락은 발사 반대쪽으로 가장 튀어나온 부분에 닿는다고 본다. 면이 정면이면 면 가운데를 밀어 곧게 가고, 비스듬히 놓였으면 꼭짓점 쪽을 밀게 되어 무게중심을 비껴 치므로 돌면서 옆으로 샌다.
- 무작위 값은 쓰지 않는다. 같은 조건이면 결과가 같고(`test/shape.mjs` S1), 어려움은 접촉 위치에 대한 민감도에서 나온다: 면으로 밀면 방향을 ±2도 흔들어도 도착점이 0.4cm 달라지지만, 비스듬하면 1.4cm 이상 달라지고 200~380도를 돈다.
- 가까운 검증 배치(15cm)는 개발자 패널의 "근거리 검증 배치로 다시 시작"과 성공 재현 프리셋에서 쓴다.

## 튕기기를 구현한 방식

- 단위: 1 = 10cm. 보통 지우개는 0.5 × 0.1 × 0.25(길이 × 두께 × 폭), 질량 1. 물리는 1/240초 고정 간격, CCD 켬.
- 충격 한 번을 무게중심에서 벗어난 점에 준다. 점은 "발사 방향 기준 뒤쪽(`hitBack`), 아래쪽(`hitHeight`)"이고, 충격은 수평 성분 + 위쪽 성분(`vAssist`)이다. 지우개의 지금 자세에서 그 방향으로 차지하는 길이를 재서 점을 잡으므로 뒤집히거나 서 있어도 계산이 같다.
- 회전은 그 충격의 토크(r × J)에서 나온다. 기본값에서는 "아래쪽을 수평으로 민 효과"가 "뒤쪽을 위로 든 효과"보다 커서 앞이 들린다(패널의 `앞 들림 토크`가 양수). `spinAssist`는 같은 축으로 더하는 회전 충격이다.
- 파워는 `impulse × 무게^0.85 × 게이지^powerCurve`에 누르는 곳과 종류별 배율을 곱한다. 궤적을 정해 두거나 상대 쪽으로 끌어당기는 보정은 없다.

## 걸침과 낙하 판정

- 걸침: Rapier의 두 지우개 사이 접촉 매니폴드에서 (1) 실제로 닿은 접촉점이 있고 (2) 접촉 법선의 세로 성분이 0.6 이상이며 (3) 접촉점이 한쪽 중심보다 아래, 다른 쪽 중심보다 위에 있을 때 "받쳐짐"으로 본다. 이 상태와 두 지우개의 저속 상태가 `perchHold`초 동안 끊기지 않아야 승리. 끊기면 타이머를 0으로 되돌린다.
- 낙하: 중심 높이가 책상 윗면 아래 10cm(-1.0)보다 내려가면 낙하. 일부만 책상 밖으로 나온 것은 낙하가 아니다. 한쪽이 떨어지면 남은 쪽이 책상 위에서 멈출 때까지 기다린 뒤 결과를 확정하고, 그 사이 남은 쪽도 떨어지면 무승부.
- 안정: 선속도·각속도가 기준 아래인 상태가 `stableHold`초(시뮬레이션 시간) 이어지면 멈춘 것으로 본다. 10초가 넘으면 기준을 3배로 풀어 미세한 떨림을 넘기고, 25초가 넘으면 "이번 차례 다시 하기" 버튼을 띄운다. 둥근 모양 위에 얹혀 제자리에서 까딱거리기만 하는 경우(2초 동안 위치 1mm, 자세 약 2도 안)는 멈춘 것으로 본다.

## 개발자 패널

오른쪽 위 "개발자 패널". 설정값은 편집 즉시 저장되지만 **다음 발사부터** 적용되고, 지금 시뮬레이션에 적용된 값과 다르면 항목에 표시된다.

- 설정: 기본값으로 / JSON 복사 / JSON 내려받기 / 가져오기(붙여 넣기 또는 파일). 범위를 벗어나거나 빠진 값은 이유와 함께 거부한다.
- 발사 재현: 방향(도)·파워(%)를 숫자로 넣어 발사, 발사 전 상태 저장·복원, 같은 조건으로 다시 발사, 성공 재현 프리셋.
- 성공 재현 프리셋: 보통 지우개끼리 기본 배치, 1P, 방향 0도, 파워 65%, 누르는 곳 가운데. "프리셋 바로 발사"를 누르면 1P가 2P 위에 올라타 승리한다.
- 지금 상태: 게임 상태, 속도, 접촉 여부, 받침 판단, 안정·걸침 유지 시간.

## 손맛을 조정할 때 먼저 바꿀 것

1. `impulse`(발사 충격량): 전체 세기. 올라타는 파워 구간이 게이지의 어디에 오는지를 정한다.
2. `vAssist`(수직 보조): 도약 높이. 낮추면 미끄러져 옆면에 부딪히고, 높이면 넘어가 버린다.
3. `gravity`(중력): 체공 시간과 묵직함. 실제 비율은 약 98이고 지금은 60으로 조금 느리게 잡았다.
4. `friction`(마찰): 착지 후 미끄러짐. 낮추면 올라탔다가 미끄러져 내려온다.
5. `angDamp`·`spinAssist`: 공중 회전량.

바꾼 뒤 `node test/tune.mjs impulse=22 vAssist=0.3`처럼 실행하면 방향·파워별 결과 지도가 나온다.

## 연출

물리 결과는 건드리지 않고 그리기와 소리에만 적용한다. 느린 화면도 계산은 같은 고정 간격으로 하고 흐르는 속도만 늦춘다(`test/browser.cjs`에서 느린 화면이 끼어도 승리 확정까지의 물리 걸음 수가 같음을 확인).

- 튕길 때: 지우개가 눌렸다 튕겨 돌아오는 찌그러짐, 뒤로 뿜는 먼지, 화면 흔들림
- 날아갈 때: 꼬리, 상대 위로 날아드는 순간 느린 화면과 확대, 위아래 검은 띠
- 착지·충돌: 찌그러짐, 먼지, 지우개 가루, 지우개끼리 세게 부딪히면 별과 "쾅!" 글자
- 걸침 확인: 색연필 동그라미, 두근거리는 화면과 소리, "올라탔다?!", 미끄러지면 "아깝다!"
- 승리: 느린 화면 → 도장 → 종이 꽃가루, 이긴 지우개가 폴짝거림
- 낙하: "앗!!", 카메라가 책상 가장자리에서 떨어지는 지우개를 내려다보며 따라감
- 차례 전환: 칠판 알림, 카메라가 책상을 돌아 넘어감

## 화면 디자인

옛날 교실과 문방구 분위기로 맞췄다. 줄 공책 쪽지(안내), 명찰(차례 표시), 칠판(차례 전환 알림), 30cm 자(파워 게이지, 빨간 빗금은 위험 구간), 색연필 동그라미(걸침 확인), "참 잘했어요" 도장(승리), 공책 표지(시작 화면). 효과음은 파일 없이 코드로 만들고 왼쪽 아래 버튼으로 끈다.

배경은 교실 한가운데 책상이다. 교실은 따로 낮은 해상도로 그려 흐리게 한 뒤 배경으로 깔고 가장자리를 어둡게 해서, 책상 위만 또렷하게 보인다. 교실과 책상은 코드로 만들었고, 직육면체 지우개만 외부 CC0 모델을 쓴다(위 "겉모습").
